# Project documentation

- Read `Docs/Decision.md` and `Docs/Flow.md` before changing architecture or project workflows.
- Record each new or changed architectural decision in `Docs/Decision.md`, including its reason, consequences, status and implementation references. Preserve superseded decisions and identify their replacements.
- Register every new or changed project flow in `Docs/Flow.md`, including its trigger, inputs, steps, outputs, side effects and failure branches. Include commands, APIs, agent handoffs, background tasks and operational/recovery workflows when applicable.
- Update both registers alongside the implementation. Keep stable ADR/flow IDs and cross-references, and clearly distinguish implemented behavior from proposals.
- Use the exact directory spelling `Docs` in repository links so they work on case-sensitive systems.
