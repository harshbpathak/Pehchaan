02 / How it works

Agents propose. The graph decides.

  1. 1

    Recall

    Has this wording been seen before? A FalkorDB vector index over past submissions answers instantly through the edges the agent wrote last time.

    FalkorDB vector index
  2. 2

    Scout

    Find recorded wordings by meaning, in many languages, then check both directions of entailment before calling anything a match.

    Multilingual embeddings · NLI
  3. 3

    Trace

    Follow claim → narrative frame → related claim → fact-check → publisher, plus native BFS and bounded paths.

    Cypher · algo.BFS
  4. 4

    Widen

    No direct match? Walk through the entities and frames the message shares with reviewed claims. Rare connections count more than hubs.

    Graph Detective
  5. 5

    Decide

    Known recycled claim, variant of a known narrative, or new. Draft a reply from graph records only, or queue it for a fact-checker.

    Evidence & Response
  6. 6

    Remember

    Write the message back into the graph, linked to what it matched, so the next forward is answered by following an edge.

    Submission write-back

03 / Tools

Eight tools. One graph.

Everything the agents can do is one of these tools, and every tool is a FalkorDB query. The same eight are served over MCP, so Claude, ChatGPT or Gemini can call them. Six are open to everyone; the two that write to the graph are reserved for the team.

  • find_similar_claimsopen to everyone

    Finds recorded wordings close in meaning to the message, in any language, then checks both directions of entailment before calling one a match.

    Behind it
    FalkorDB vector index (db.idx.vector.queryNodes) + a local NLI model
    Used by
    Claim Scout
    Returns
    matches, related context, rejected candidates, and the ids handed to the detective
  • get_claim_evidenceopen to everyone

    Returns the publisher records behind one recorded wording: the URL, the original rating, the review date and the provenance of the source file.

    Behind it
    Cypher over CHECKS and PUBLISHED_BY
    Used by
    Evidence & Response
    Returns
    one record per fact-check of that wording
  • explore_narrative_graphopen to everyone

    Walks claim → narrative frame → related claims → their fact-checks and publishers, returning each path with the basis of every inferred edge.

    Behind it
    fixed multi-hop Cypher (NARRATIVE_PATHS)
    Used by
    Graph Detective
    Returns
    paths with node ids, relationship types and who inferred each edge
  • find_evidence_pathopen to everyone

    Finds the shortest connection between two recorded claims through shared frames and entities, up to eight hops in either direction.

    Behind it
    algo.SPpaths
    Used by
    Graph Detective
    Returns
    the path as node ids and relationship types, or nothing
  • expand_narrative_contextopen to everyone

    Tags the message with frames and entities, then finds fact-checked claims that share them. Rarer nodes weigh more; hits that share only a hub or a place are dropped.

    Behind it
    SHARED_CONTEXT Cypher scored by 1/degree
    Used by
    Graph Detective, when there is no direct match
    Returns
    related claims with the nodes they share, as context, never evidence
  • assemble_evidence_dossieropen to everyone

    Runs the whole investigation read-only: recall, scout, trace, widen, decide, draft the reply. Nothing is saved.

    Behind it
    all of the above, in one call
    Used by
    this page, and any MCP client
    Returns
    the full dossier with citations, finding, drafted reply and the agent timeline
  • investigate_claimteam only

    The same investigation, then saved: an Investigation node with exact EXAMINES and CITES edges, and the message written back as a Submission with MATCHES edges.

    Behind it
    MERGE writes into the same graph
    Used by
    the team, with the write token
    Returns
    the saved case; a reworded repeat is later answered through its edges
  • create_review_caseteam only

    Investigates and files the case for human review whatever the finding, for messages a researcher wants looked at regardless.

    Behind it
    the investigation above with the review flag set
    Used by
    the team, with the write token
    Returns
    the saved case, queued at high priority

Inside the server the specialists also call breadth_first_search (algo.BFS) and recall_prior_submission (a vector index over past messages); those are not exposed over MCP. A tool call outside a specialist's fixed list is refused and recorded in the timeline.

Beyond finding similar wording

  • Native paths. A four-hop Bill Gates bridge connects vaccine-microchip and climate claims using algo.SPpaths.
  • Submission memory. Near-identical forwards reuse MATCHES. Input embedding and source reads still run; fresh NLI and hosted-LLM calls are skipped.
  • Context widening. Shared entities and frames reach related reviews, weighted by rarity. Context can trigger human review; it is not a direct fact-check.
  • Source provenance. Inspect original publisher ratings and inferred-edge basis. Shared connections do not prove truth or coordination.
  • MCP access. Six public read-only tools and two protected case-writing tools use the same graph.

MCP discovery and calls were checked with the official client. End-to-end coding-agent verification is a separate check.
